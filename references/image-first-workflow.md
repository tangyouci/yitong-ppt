# Image-first workflow for complex slides

Use this workflow for visually complex overview, architecture, mechanism, system, or hero slides. Do not require it for simple editable text, chart, table, or comparison pages.

## Build the fact block

Before generating a draft, define:

- report route and audience;
- page role and title;
- supported challenge, process, evidence, and takeaway;
- available source visuals;
- facts and visual elements that must not be invented.

## Prompt skeleton

```text
Create one polished 16:9 presentation slide.

REPORT ROUTE: [academic / project]
AUDIENCE: [audience]
PAGE ROLE: [problem / overview / method / result / roadmap / summary]
TITLE: [short title]
SUPPORTED CONTENT: [facts, process, evidence, and conditions]
AVAILABLE VISUALS: [figures, screenshots, plots, scenes, diagrams]
TAKEAWAY: [one supported sentence]
DO NOT INVENT: [missing or unsupported details]

Use a clear hierarchy, stable margins, concise text, and evidence-led visuals.
Default visual language: light background, strong black structure, selective red emphasis, and at most one restrained secondary color. Follow an attached user template when supplied.
```

## Review the draft

Check content correctness before visual polish. Reject or revise generated text, numbers, charts, logos, identities, citations, and process steps that are unsupported or malformed.

Approve the design based on hierarchy, composition, information flow, and visual density—not on pixel-perfect text. The editable reconstruction remains the authoritative deliverable.
